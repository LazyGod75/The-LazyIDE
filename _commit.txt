fix(lazybot): prune zombie bot runs at boot so launches are never blocked

A LazyBot run whose mission was interrupted by an app restart stayed
"running" in .lazy/bot-runtime.json forever: the runMission chain that would
have called finishBotRun died with the process. restoreBotRuntime rehydrated
the zombie on every boot, so the bot could never launch again ("already has N
concurrent run(s) (max N)") and its canvas node stayed stuck on "Working".

- botRuntimeStore: removePersistedRuns() prunes the runtime file in place
  without touching unrelated persisted runs.
- botEngine: pruneBotRunsNotLive(liveMissionIds) ends every run (in-memory
  AND on-disk, before or after restoreBotRuntime) whose mission the boot
  recovery pass did not leave live (running/queued). Idempotent, best-effort.
- agentsStore: runs the prune from both boot recovery paths (journal
  applyReplayRecovery + legacy missions.json fallback), unions in missions
  launched while the boot load was in flight, finishes bot-run bookkeeping
  when a queued bot mission relaunched at boot settles, and hardens
  run_lazybot auto-recovery so it only clears runs whose mission is present
  and terminal (never a genuinely live run of another project).
- botVmState: pin the last-VM-state map on globalThis (Vite dev double module
  instances could otherwise split live VM state between instances).
