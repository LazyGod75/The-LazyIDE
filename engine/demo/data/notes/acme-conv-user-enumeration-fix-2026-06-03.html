Security Fix ? Prevent User Enumeration on Login Endpoint

Fixed a user enumeration vulnerability in the POST /auth/login handler in src/api/routes.ts. The original implementation returned 404 Not Found when the email did not exist in the database, which allowed an attacker to enumerate valid email addresses by observing whether the response was 404 (email not found) or 401 (wrong password).

Fix: both cases now return 401 Unauthorized with the same generic message "Invalid credentials". The timing of the response is also equalized ? even when the user is not found, we still perform a dummy bcrypt comparison to prevent timing side-channel attacks where a fast 404 response reveals that the email does not exist.

This fix follows the OWASP guidance on preventing user enumeration at authentication endpoints. Combined with the rate limiting we should add to the middleware, this significantly hardens the login endpoint against automated attacks.
