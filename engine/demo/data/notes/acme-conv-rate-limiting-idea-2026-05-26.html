Rate Limiting ? Add to Auth Endpoints

Idea: we should add rate limiting to the /auth/login endpoint in src/api/middleware.ts to prevent brute-force password attacks. The current implementation has no limit on login attempts per IP, which would allow an attacker to test millions of password combinations against known email addresses.

The recommended approach is exponential backoff rate limiting per (IP + email) combination stored in Redis. Using the existing redisCacheUrl connection in src/config.ts, we could use the express-rate-limit package with the rate-limit-redis store. Start with 10 attempts per 15-minute window, doubling the lockout period after each threshold breach.

Should also add rate limiting on the /webhooks/stripe endpoint to prevent DoS via fake webhook floods, though in practice Stripe's IP allowlist is a better first line of defense there.
