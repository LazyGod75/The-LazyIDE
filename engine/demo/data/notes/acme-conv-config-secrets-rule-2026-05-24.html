Configuration Rule ? All Secrets via Environment Variables

We established a rule for src/config.ts: all secrets and credentials must always come from environment variables, never from config files or hardcoded values. The requireEnv helper throws at startup if a required variable is missing rather than falling back to a default ? this prevents silent misconfiguration in production where a missing secret might cause the service to run in a degraded state without anyone noticing.

The startup-fail-fast approach is intentional: it is better to refuse to start than to run with missing payment credentials. A failed deployment is visible and recoverable; silent data loss from missing Stripe keys is not.

We should also add a secrets rotation runbook for JWT_SECRET and STRIPE_SECRET_KEY ? these should be rotatable without downtime using a dual-key validation window. This is currently not implemented but should be added before GA launch.
