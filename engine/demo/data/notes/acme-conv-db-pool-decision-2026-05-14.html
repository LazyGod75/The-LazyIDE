Database Client ? pg over Prisma for Core Pool

We decided to use the pg (node-postgres) library directly rather than Prisma for the core connection pool in src/db/client.ts. Complex analytics queries in the billing module require raw SQL with window functions and CTEs that do not map well to Prisma's query builder.

Prisma is still used exclusively for schema migrations (the declarative schema is valuable for version-controlled migration history), but all runtime queries go through the pg pool. This gives us both migration safety and query flexibility.

We chose a max pool size of 20 connections ? this matches our Postgres instance's max_connections divided by 5, leaving headroom for migrations and monitoring connections. Idle timeout set to 30 seconds to prevent stale connections from accumulating under low traffic.
