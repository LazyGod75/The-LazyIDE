Authentication Middleware ? 401 vs 403 Rule

We established a rule for the authentication middleware in src/api/middleware.ts: always return 401 Unauthorized when the token is missing or invalid, never 403 Forbidden. The HTTP spec is clear: 403 means the server understood the request but the authenticated user lacks permission, while 401 means the request requires authentication or the credentials are invalid.

This distinction matters for client-side error handling: a 401 should trigger a redirect to the login page, while a 403 should show an "access denied" UI without redirecting. Mixing them up causes confusing UX where logged-in users are sent back to the login screen when they try to access admin-only routes.

Updated src/api/routes.ts to use the authenticate middleware on all protected routes, and added the requireRole factory for role-based access control on admin endpoints.
