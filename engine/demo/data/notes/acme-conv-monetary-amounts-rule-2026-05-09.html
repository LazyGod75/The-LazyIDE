Monetary Amounts ? Always Integer Cents

We decided on a rule: all monetary amounts must always be stored and transmitted as integer cents (smallest currency unit). Never use floating-point dollar amounts anywhere in the codebase ? not in the database schema, not in API responses, not in internal calculations.

Rationale: floating-point arithmetic on currency values causes rounding errors that compound over time. A payment of $9.99 represented as 0.0999 * 100 can produce 9.990000000000001 cents. Using integer cents eliminates this class of bug entirely.

The Stripe API itself always returns amounts in cents, so there is no conversion needed at the boundary. Updated src/payments/stripe.ts and src/payments/webhooks.ts to use amountCents variables throughout, and updated src/db/client.ts comments to reflect this convention.
