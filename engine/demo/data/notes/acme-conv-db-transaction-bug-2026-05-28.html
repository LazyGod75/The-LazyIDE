Bug: Database Transaction Not Rolling Back on Partial Failure

Discovered a bug where the transaction helper in src/db/client.ts was not correctly calling ROLLBACK when the user callback threw an error. The original implementation used a try/catch but the finally block released the client before the ROLLBACK completed, causing the connection to return to the pool with an open transaction.

This crash left the database connection in an inconsistent state where subsequent queries on that connection would receive "ERROR: current transaction is aborted, commands ignored until end of transaction block" errors. The bug was intermittent and hard to reproduce in development but surfaced under load testing.

Fix: restructured the transaction method in src/db/client.ts to always run ROLLBACK before releasing the client in the catch block, and updated src/auth/session.ts to use the transaction wrapper for createSession to ensure the session insert and JWT signing are atomic. Added explicit error logging for ROLLBACK failures (though those are very rare in practice).
