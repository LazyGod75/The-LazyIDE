Fixed Token-Refresh Race Condition in session.ts

Discovered a race condition in the createSession function in src/auth/session.ts. The original implementation generated the session ID after inserting to the DB, causing a window where the signed JWT referred to a session that did not yet exist in the sessions table.

Bug reproduction: under high concurrency, a client could receive a valid JWT but immediately get a 401 on their first authenticated request because the session row was not yet committed when the middleware checked it.

Fix: now we generate the session ID first using crypto.randomUUID(), then insert the session row, then sign the JWT ? eliminating the race window entirely. The fix also simplifies the control flow since the session ID is available at signing time.
