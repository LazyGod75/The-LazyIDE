API Response Envelope ? Standard Format Across All Routes

We decided on a rule: all API endpoints in src/api/routes.ts must always return the standard ApiResponse envelope format: { success: boolean, data?: T, error?: string }. This applies to both successful responses and error responses ? never return a naked object or a bare error string.

The envelope makes client-side error handling predictable: clients always check response.success first, then read response.data on success or response.error on failure. It also enables transparent middleware logging and tracing since the envelope structure is consistent.

Updated all existing route handlers in src/api/routes.ts to use this envelope and updated the global error handler in src/api/middleware.ts to format thrown errors through the same envelope in production mode (hiding internal details) and development mode (exposing the full error message).
