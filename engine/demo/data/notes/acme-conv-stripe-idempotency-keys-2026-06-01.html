Idempotency Keys for Stripe API Calls

Idea: we should add idempotency keys to all Stripe API calls that create or modify resources in src/payments/stripe.ts. Stripe supports idempotency keys on POST requests to prevent double-charging when network retries occur. Currently only createSubscription uses an idempotency key.

The idempotency key for createSubscription is derived from userId + priceId + date, providing per-day idempotency. This means a customer can safely retry a failed subscription creation within the same day without risk of being charged twice. We should use a similar pattern for any future charge or payment intent creation.

Should also evaluate whether to store the idempotency key in our own database to enable cross-service idempotency (not just within Stripe's 24-hour window). This would matter if we ever replay failed operations from a message queue.
